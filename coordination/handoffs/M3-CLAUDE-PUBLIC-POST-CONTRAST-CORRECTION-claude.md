## Defect

DeepSeek's independent Chromium QA of the merged Berita public reference slice
(`origin/ai/deepseek/m3-public-post-experience-qa` at `483352b`) reported a
WCAG 2.1 AA color-contrast failure on the "Berita Terbaru" sidebar `<time>`
label in `src/components/public/post/post-sidebar-latest.tsx`:
`text-slate-400` (`#90a1b9` on `#ffffff`) measured `2.63:1`, below the
required `4.5:1` for normal text.

## Contrast decision

Replaced `text-slate-400` with `text-slate-500` — an existing FUSPI palette
utility already used for the same purpose (secondary/muted meta text next to
a `<time>` element) in the sibling component
`src/components/public/post/post-meta-row.tsx` (forbidden path, read for
convention only, not edited). `slate-500` (`#64748b`) is also the palette
value backing the installed `--muted-foreground` semantic token in
`src/app/globals.css` (light mode).

Computed contrast of `#64748b` on `#ffffff` (WCAG relative-luminance
formula): **4.76:1**, which clears the required `4.5:1` for normal-size text.
No new token, no `globals.css` edit, no dependency change.

Nothing else in the component changed: `<time dateTime>`, locale/RTL
behavior (`lang`/`dir` on the title span), focus behavior, title wrapping
(`line-clamp-2 break-words`), cover presentation, hover treatment
(`group-hover:bg-slate-50` / `group-hover:text-royal-600`), and sidebar
structure are all untouched. Header/footer contrast and every other public
Berita acceptance area were left as-is per the manifest's bounded-correction
scope.
